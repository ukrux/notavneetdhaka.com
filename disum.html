Disum

Disum is a dark, atmospheric isometric puzzle game for mobile. You roll a 3D die across mysterious environments and match the right face to glowing nodes to unlock the path forward.

It starts as a simple spatial puzzle and grows as new mechanics, hazards and environmental challenges appear. Built around the lore of the Disum Curse, it pairs an eerie, premium look with easy controls and puzzles that make you think several moves ahead.

My design breakdown

How it works

01

Rolling the Die

Core mechanic

The die moves one tile at a time. Every step tips it over, so the face on top changes with each move. Number tiles only open when the face on top matches the number on the tile.

This turns simple movement into the puzzle itself. The player isn't just finding a path to the goal. They're finding a path that makes the right face land in the right place. Every move changes what the die will show next, so players learn to plan a few rolls ahead instead of just walking forward.

02

Puzzle Nodes

The steps before the final match

Each level is built from smaller puzzles. The player clears these first, and only then reaches the core puzzle: the final Number Match. This keeps each level varied while always ending on the main idea of the game.

Pressure Plate

Plates open doors, but the die alone isn't enough to hold one down.

Pattern Match

Light up tiles with the die to copy a pattern shown next to the platform.

Spikes

Spikes rise and fall in a rhythm the player has to read and time.

Directional Arrows

Stepping on an arrow tile turns its arrow by 45°, and the arrow changes color when it points the right way. Line up every arrow to reveal the number on the number tile.

03

Fixing the Spike Soft-Lock

A problem I solved

The problem
In the first version, spikes switched up and down on every single move, based on one on/off signal. If the player started next to a raised spike, the timing always lined up so the die landed on it. There was no way through. The level was soft-locked.
The fix
I rebuilt spike movement around an offset pattern. Instead of flipping every move, each spike follows a short cycle, like up-up-down or down-down-up. Now there's always a safe window, and players can count their moves to slip past.
The bonus
We made the pattern customisable for each spike. Different spikes can run different rhythms, so a single row of spikes can become its own small timing puzzle.

04

Verticality

Later in the game

Later levels add height. To reach higher platforms, the player has to use a duplicate cube as a step to climb. This takes the same rolling rules into a new direction: now the player plans upward as well as across the board.

05

Difficulty & Pacing

Chapter 1 · 12 levels

In the current build, Chapter 1 has 12 levels, and a new mechanic arrives at levels 3, 6, 8 and 10. The levels in between let players practise each new idea before the next one lands.

06

Swipe Controls

Designing for mobile

We built and tested two versions: on-screen buttons and swipes. Swipes felt smoother and gave players more freedom. The buttons were hard to hit and quickly got annoying.

There was a technical reason too. Buttons would need constant adjusting for different screen sizes, while swipes work the same on any phone. For a game where every single move matters, the control should feel invisible, so we went with swipes.

07

Technical Art

VFX & shaders

I made all of the game's VFX, including the portal, the spawn effect and the level complete effect. I built them with Shader Graph and Unity's particle system, and made the tile patterns in Photoshop.

In a dark game like this, light does a lot of work. The glowing tiles and effects tell the player where to look and what matters, without needing extra UI.

08

UI/UX

Prototype stage

The UI is still a prototype, kept simple so we could focus on the puzzles first. In final production, it will get a full art pass with a strong art style to match the world of Disum.
